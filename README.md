# Reminderly — сервис напоминаний (ПР7 + CRUD)

Индивидуальный учебный проект Python 3.11+ / Django 5.2. Последовательно развивается от консольной версии ПР1–ПР3 через Django и шаблоны ПР5–ПР6 к **SQLite, SQL и sqlite3 (ПР7)**.

В ПР7 реализованы **5 связанных таблиц, импорт данных из JSON, 29 SQL-запросов, получение результатов в Django, поиск по всем пяти сущностям и статистика**. Дополнительно реализован **полный веб-CRUD** пяти сущностей: создание, просмотр, редактирование, удаление. Django ORM для предметных сущностей не используется: это отдельная тема следующих работ. Консольная программа и старые JSON-файлы сохранены.

## 1. Быстрый запуск

ZIP уже содержит заполненную базу `data/reminderly.sqlite`, поэтому **для просмотра страниц достаточно установить зависимости и запустить сервер**.

macOS / Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py check
python manage.py migrate
python manage.py runserver
```

Windows PowerShell:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py check
python manage.py migrate
python manage.py runserver
```

Открыть <http://127.0.0.1:8000/>. Служебная `db.sqlite3` создаётся Django при `migrate` отдельно от `data/reminderly.sqlite`, где хранятся данные напоминаний. Bootstrap подключается через CDN, а собственные CSS/JS и логотип доступны локально.

Консольную версию ПР3 запустить командой `python main.py`. Она **по-прежнему работает с JSON**, не с SQLite.

## 2. База данных и связи

Пять сущностей (`User`, `Category`, `Time`, `Task`, `Reminder`) сопоставлены с таблицами:

| Таблица | Поля | Внешние ключи |
| --- | --- | --- |
| `users` | `id INTEGER PK`, `name TEXT`, `email TEXT UNIQUE` | — |
| `categories` | `id INTEGER PK`, `name TEXT UNIQUE`, `description TEXT` | — |
| `times` | `id INTEGER PK`, `label TEXT`, `moment TEXT` | — |
| `tasks` | `id INTEGER PK`, `title TEXT`, `description TEXT`, `user_id INTEGER`, `category_id INTEGER`, `is_completed INTEGER` | `user_id → users`, `category_id → categories` |
| `reminders` | `id INTEGER PK`, `text TEXT`, `category_id INTEGER`, `remind_at TEXT`, `user_id INTEGER NULL`, `task_id INTEGER NULL`, `time_id INTEGER NULL` | `category_id → categories`, `user_id → users`, `task_id → tasks`, `time_id → times` |

Физическая схема — `sql/schema.sql`; база — `data/reminderly.sqlite`. В SQLite время сохраняется в ISO-формате `YYYY-MM-DDTHH:MM`, логические значения — `0/1`. В отличие от JSON, где у напоминания категория записана строкой, SQLite хранит `category_id`. При импорте выполняется сопоставление с таблицей `categories`.

`db/database.py` создаёт соединение через `sqlite3.connect()`, включает `PRAGMA foreign_keys = ON` и устанавливает `sqlite3.Row`. Поля результата доступны по именам. Все пользовательские параметры передаются через `?`, а не через конкатенацию SQL. `db/init_db.py` создаёт таблицы, `db/import_json.py` переносит все пять JSON-коллекций с проверкой связей и транзакцией.

### Пересоздание базы из JSON

Эти команды необязательны при первом запуске; они нужны для демонстрации импорта или восстановления БД.

```bash
python -m db.init_db
python -m db.import_json
```

**Важно:** повторный `import_json` заменяет содержимое пяти таблиц текущими JSON-данными. Если вы изменяли записи непосредственно в SQLite, не запускайте импорт повторно без необходимости. JSON не меняется при чтении страниц сайта.

Для просмотра структуры из Python:

```bash
python -c "from db.database import get_connection; c=get_connection(); print(c.execute(\"SELECT name FROM sqlite_master WHERE type='table'\").fetchall()); c.close()"
```

Для проверки SQL в SQLite CLI: `sqlite3 data/reminderly.sqlite`, затем `.read sql/queries.sql`, `.exit`. Некоторые запросы содержат `?` — их удобно проверять в `sqlite3` через `.parameter init` / `.parameter set ?1 ...`, либо вызывать `sqlite3.execute(sql, params)` из Python, как в тестах.

## 3. SQL-запросы

Все **29 запросов** содержатся в `sql/queries.sql` с комментариями вида `-- name: joined_tasks`. Модуль `db/database.py` читает их по именам; это позволяет использовать в Django те же запросы, что тестировались непосредственно в SQLite.

Запросы покрывают обязательные группы, минимум по два запроса в каждой:

1. **SELECT (списки):** пользователи, категории, время, задачи.
2. **WHERE:** задачи по статусу, напоминания до даты, записи пользователя или категории.
3. **JOIN:** задачи с пользователем и категорией, напоминания с пользователем, задачей, категорией и временем.
4. **Агрегаты:** общее число напоминаний, число выполненных задач, показатели главной страницы.
5. **GROUP BY / HAVING:** задачи по категориям и пользователям, напоминания по категориям, пользователи с указанным минимумом задач.

SQL выполняется функциями `fetch_all()` и `fetch_one()` с закрытием соединения в `finally`.

## 4. Веб-интерфейс на SQLite

Существующие страницы полностью сохранены, но **Django views теперь читают данные из SQLite**, а не из `load_project_data()`.

| URL | Сценарий |
| --- | --- |
| `/` | Количество всех пяти сущностей из SQL |
| `/reminders/` и `/reminders/<id>/` | Напоминания и связи; встроенные поиск по тексту, категория, дата, статус |
| `/tasks/` и `/tasks/<id>/` | Задачи; поиск по названию/описанию, статус и категория |
| `/tasks/?status=open` и `?status=done` | Фильтрация задач через SQL `WHERE` |
| `/users/` и `/users/<id>/` | Пользователи и их задачи/напоминания; поиск по имени и email |
| `/categories/` и `/categories/<id>/` | Категории и связанные записи; поиск по названию/описанию |
| `/times/` и `/times/<id>/` | Плановые моменты; поиск по названию и выбор даты |
| `/reminders/?q=домашнее&category=1` | Поиск прямо над списком напоминаний (GET); `/search/` остаётся совместимым адресом |
| `/statistics/` и `/statistics/?min_tasks=2` | COUNT, SUM, GROUP BY и HAVING на реальных данных |

**Поиск находится над списком в каждом из пяти разделов, отдельного пункта «Поиск» в меню больше нет.** Все фильтры можно комбинировать; «Сбросить» возвращает полный список. Поиск выполняется параметризованным SQL (`?`), без Django ORM. Старый `/search/` показывает тот же интерфейс списка напоминаний для совместимости, а форма отправляет GET на `/reminders/`.

Все страницы используют шаблоны ПР6 (`render()`, `base.html`, `include`, `{% url %}`, статические файлы). Помимо обязательной части ПР7 добавлены формы полноценного CRUD. POST на GET-only страницы списков/поиска и статистики возвращает HTTP 405. Несуществующие записи отдают 404; при ошибке SQLite показывается страница 500.

### Дополнительно: управление записями (CRUD)

Для **каждой** из пяти сущностей (`users`, `categories`, `times`, `tasks`, `reminders`) предусмотрены маршруты:

- `/<раздел>/` — список и кнопка «+ Добавить»;
- `/<раздел>/new/` — форма создания (GET), запись в SQLite (POST);
- `/<раздел>/<id>/` — страница записи с кнопками «Редактировать» и «Удалить»;
- `/<раздел>/<id>/edit/` — редактирование записи через форму (GET/POST);
- `/<раздел>/<id>/delete/` — подтверждение (GET) и удаление (POST).

Сохранение выполняется **в SQLite через `sqlite3`**, без `ModelForm` и без Django ORM. `planner/forms.py` содержит обычные формы Django и серверную проверку входных данных. `planner/crud_views.py` обрабатывает HTTP-операции. `db/crud.py` выполняет `INSERT` / `UPDATE` / `DELETE` с параметрами `?` и транзакциями. Список допустимых таблиц и полей фиксирован в коде (невозможно подставить название таблицы из пользовательского ввода). Формы защищены CSRF-токеном.

При создании задачи выбираются **существующие пользователь и категория**. Напоминание может быть связано с пользователем, задачей и временем (связи необязательные). Если выбрана задача, её категория должна совпадать с категорией напоминания, а при выбранном пользователе — совпадать и пользователь. Если выбрано связанное время, его дата должна совпадать с датой напоминания. При редактировании уже связанных задач и объектов времени конфликтующие изменения блокируются до изменения соответствующих напоминаний.

**Удаление без каскада:** SQLite не позволит удалить пользователя, категорию, задачу или время, пока на них ссылаются другие записи. На странице будет показано понятное сообщение. Сначала измените или удалите зависимые напоминания/задачи; затем повторите удаление родительского объекта.

Данные, изменённые через сайт, сохраняются **только в `data/reminderly.sqlite`**, JSON-данные консольной версии автоматически не обновляются. Не запускайте `python -m db.import_json` после создания записей через сайт без необходимости: повторный импорт заменит содержимое SQLite исходными JSON-данными.

**Область применения:** учебная локальная демонстрация. В проекте пока нет аутентификации и разграничения прав доступа к CRUD, поэтому не публикуйте этот сервер в открытом интернете.

## 6. Проверка

```bash
python manage.py check
python -m pytest -v
python -m flake8 . --extend-exclude=.venv,venv
```

В `tests/test_pr7_database.py` проверяются 5 таблиц, FK, целостность, импорт, 29 запросов, SQL-поиск и агрегации. В `tests/test_pr7_web.py` проверяются реальные Django-страницы, поиск, фильтры и обновление данных в SQLite без изменения JSON. В `tests/test_pr7_crud_database.py` — SQL-CRUD, целостность связей, уникальность и SQL-инъекции. В `tests/test_pr7_inline_search.py` и `tests/test_pr7_inline_search_web.py` — поиск на пяти страницах списков и фильтрация в SQLite. В `tests/test_pr7_crud_web.py` — создание/редактирование/удаление всех пяти сущностей, валидация форм, запрещённое удаление зависимых записей и CSRF. Сохранены прежние тесты предметной области, консольной логики и шаблонов.

**Ограничение сборки:** в среде создания архива не были доступны пакеты Django и flake8. Поэтому здесь запущены офлайн-тесты `pytest`; тесты Django пропускаются (`pytest.importorskip`). После `pip install -r requirements.txt` требуется повторить полный набор и `manage.py check` локально.
